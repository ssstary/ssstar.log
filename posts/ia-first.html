IA(정보구조) 설계, 처음 해봤습니다

기획자 공부를 시작하며 처음으로 사이트맵과 IA를 직접 설계해본 과정을 기록했습니다.

#IA #정보구조 #기획공부

기획자 공부를 시작하고 처음으로 제대로 된 IA를 직접 설계해봤습니다. 퍼블리셔로 일할 때는 IA가 이미 완성된 상태에서 작업을 받았기 때문에, 그것을 직접 만든다는 게 어떤 건지 막연했습니다.

해보니 퍼블리셔 경험이 의외의 방식으로 도움이 됐습니다.

IA가 뭔지 알면서도 몰랐던 것

IA(Information Architecture, 정보구조)는 서비스의 콘텐츠를 어떻게 조직하고, 어떤 순서로 배치하며, 어떻게 탐색하게 만들 것인지를 설계하는 작업입니다. 쉽게 말하면 사이트맵과 메뉴 구조를 결정하는 일입니다.

개념은 알고 있었습니다. 그런데 막상 처음부터 직접 설계하려니 어디서부터 시작해야 할지 막막했습니다. 퍼블리셔 시절엔 IA가 이미 나온 기획서를 받았으니까요.

어떻게 시작했나

연습용으로 익숙한 서비스 하나를 골라서 역으로 분해해봤습니다. 실제로 사용하는 앱을 열고, 메뉴를 탐색하면서 구조를 직접 그려보는 방식이었습니다.

  • 1단계: 서비스의 주요 메뉴를 모두 나열
  • 2단계: 각 메뉴 하위의 콘텐츠와 기능 목록화
  • 3단계: 관계와 계층 구조 정리
  • 4단계: 사용자가 어떤 경로로 이동할지 흐름 그리기

처음엔 Figma로 깔끔하게 만들려다가, 먼저 종이에 손으로 그렸습니다. 정확하게 만드는 것보다 구조를 빠르게 파악하는 게 먼저였습니다.

퍼블리셔 시절 경험이 의외로 도움됐다

IA를 설계하면서 막히는 지점이 있었습니다. "이 기능은 어느 메뉴 아래에 들어가야 하지?" 하는 고민이었습니다.

그때 도움이 된 건 퍼블리셔 시절 경험이었습니다. 수많은 서비스의 HTML 구조를 짜면서, 어떤 콘텐츠가 어떤 영역에 속하는지를 수없이 판단했습니다. section과 article을 구분하고, nav 안에 무엇을 넣을지 결정하는 것이 사실 정보 계층을 판단하는 작업이었습니다.

HTML 시맨틱 구조를 잘 짜는 것과 IA를 설계하는 것은 결국 같은 사고방식이었다.
시맨틱 HTML과 IA의 연결: <main>, <nav>, <section>, <aside>를 적절히 쓰는 것은 단순한 코딩 습관이 아니라, 콘텐츠의 역할과 위계를 명확히 정의하는 작업입니다. 이 감각이 IA 설계에 그대로 쓰였습니다.

처음 해보며 느낀 어려운 점

사용자 관점에서 생각하는 게 생각보다 어려웠습니다. 저는 서비스를 만드는 사람 관점에 익숙해져 있었기 때문에, "이 기능이 어디 있어야 직관적인가"보다 "이 기능은 이 카테고리에 논리적으로 맞다"는 방식으로 먼저 생각했습니다.

사용자가 어떤 목적으로 서비스를 찾는지, 어떤 언어로 메뉴를 인식하는지를 생각하는 훈련이 필요하다는 걸 느꼈습니다.

마치며

IA는 화면이 아니라 생각을 설계하는 작업이었습니다. 사용자가 어디 있고, 어디로 가고 싶고, 어떻게 거기 닿을 수 있는지를 그리는 일이었습니다.

퍼블리셔 시절 HTML 구조를 고민하던 감각이 여기서도 쓰인다는 게 흥미로웠습니다. 다음번엔 사용자 인터뷰 기반으로 카드 소팅을 활용해 IA를 검증하는 방법을 공부해볼 예정입니다.
